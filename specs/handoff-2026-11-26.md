## 已确定的后端边界

- Java 21，启动目录 `src/backend`，使用 `mvnw.cmd spring-boot:run`；数据库/JWT/管理员环境变量见该目录 README。默认不创建管理员，不提供公共默认密码。浏览器本地开发使用 Vite `/api` 代理指向后端，微信真机填写可访问的服务地址；本次未开放任意来源 CORS。
- 所有业务路径前缀 `/api/v1`。成功信封 `{"code":"OK","data":...,"message":""}`；失败同时检查 HTTP 状态及 `code`，`data` 为 null。
- JWT 通过 `Authorization: Bearer <accessToken>` 发送。401 清除登录态；403 表示当前身份无权限，不当成网络错误。改密成功后全部旧令牌失效，必须重新登录。公开浏览建议不携带过期 JWT，携带无效 JWT 仍会被拒绝。
- 公开 GET：`/posts`、`/posts/{id}`、`/posts/{id}/comments`、`/media/{id}/content`。注册/登录公开；`/admin/**` 仅 ADMIN；其他接口需认证。媒体读取还要检查其所属动态可见性。
- 分页从 1 开始，`pageSize` 为 1–50，返回 `items/page/pageSize/total`。日期 `from/to` 为 YYYY-MM-DD，按北京时间自然日包含两端；日期与单个 `tag` 取交集。
- 正式迁移已登记 V1 users、V2 admin_operation_logs、V3 posts/tags/post_tags、V4 media、V5 ratings/comments。禁止修改已应用的正式迁移；后续改表新增 V6 起的迁移，先由 M01 协调编号。独立模块测试里的 V 编号只用于测试，不能直接搬入主工程。
- `IdentityPort` 的真实实现由 M01 提供，身份来自 `UserProfile(id,account,nickname,role)`；事务内锁用户行并复查角色、ACTIVE、令牌版本。已验证版本在 Authentication.details，不能从 credentials 或客户端正文读取。
- `AdminAuditPort` 由 M01 实现；动态管理删除写 DELETE_POST 审计并参加调用事务。`UserDisabledCleanup` 已同步调用 `AuthorPosts.hideByAuthor`、`InteractionService.cleanupDisabledUser`，均加入禁用事务；不得另加重复监听器、异步监听或 REQUIRES_NEW。

## M03：媒体与运行环境

**当前问题：**主工程已装配媒体服务，但本轮 M01 验证没有覆盖真实图片/视频上传、文件读取、Range 和过期清理；独立模块测试结果不能代替此项。

**处理方法：**在主工程真实账号下验证上传→使用返回 ID 发帖→匿名读取→删除/禁用后不可读；测非法格式、10 MB 图片、50 MB MP4 边界及 Range 206/416。确认存储目录权限、重启后读取和过期清理，补运行说明与实际证据。

**接口确认：**POST `/media` 用 multipart 字段 `file`，携 JWT；返回 data 中 `id/mediaId/type/mimeType/size/url/status/createdAt`，size 为字节数。发帖传 mediaIds，不传本地临时路径。GET `/media/{id}/content` 返回二进制，可带 Range；未绑定或所属动态不可见返回 404。相对媒体 URL 拼后端 origin，不拼到小程序页面地址。主工程 multipart 上限 50 MB/请求 52 MB，业务检查图片 10 MB、视频 50 MB。
