# 系统设计

状态：**初版开发约定**。技术栈与核心业务规则已确定；M02 动态模块已建立独立工程，完整系统和跨模块联调进度以 `tasks.md` 为准。模块接入方案见 `decisions/0002-m02-independent-module.md`。

## 1. 总体结构

```text
用户小程序 ─┐
            ├─ HTTP API ─ 服务端 ─ 数据库 / 媒体文件存储
管理后台 ───┘
```

小程序和管理后台不直接访问数据库或彼此的本地文件。用户操作、管理员操作都由服务端完成身份鉴别、权限判断和数据校验。

## 2. 模块职责

| 模块 | 主要职责 |
| --- | --- |
| 用户与认证 | 注册/登录、密码设置与修改、角色权限 |
| 动态与媒体 | 图文视频上传、动态增删改查、作者权限校验 |
| 标签与检索 | 标签关联、按日期/标签筛选、结果分页 |
| 互动 | 评分、评论、评分汇总展示 |
| 管理后台 | 用户和动态的查询、删除、管理权限校验 |
| 扩展能力 | 好友、过滤、视频处理、大模型、活跃统计，按选定加分项增补 |

## 3. 初步数据对象

`User`（用户及管理员角色）、`Post`（动态）、`Media`（媒体文件）、`Tag`（标签）、`PostTag`（动态标签关联）、`Rating`（评分）、`Comment`（评论）。字段、唯一约束和索引见 `contracts/data-model.md`；数据库结构通过 Flyway 迁移文件维护。

## 4. 关键设计约束

- 用户只可修改和删除自己的动态；管理员按角色管理所有用户及动态。服务端必须校验权限。
- 上传校验文件类型、大小和归属关系；文件保存在服务端本地目录，数据库只保存元数据和存储键。
- 密码不能明文存储；服务端对输入进行校验，并统一处理错误响应。
- 检索和管理列表应支持分页，避免一次加载全部内容。
- 视频使用 MP4 文件播放，并支持 HTTP Range 请求；转码和分段流属于加分项。

## 5. 技术架构

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 用户小程序 | uni-app、Vue 3、TypeScript | 页面、上传与播放、请求服务端 API |
| 管理后台 | Vue 3、TypeScript、Vite、Element Plus | 管理员登录、用户和动态列表、查询与删除 |
| 服务端 | Java 21、Spring Boot 3.5、Spring Web、Spring Security | REST API、认证与权限、业务规则、媒体访问 |
| 数据访问 | Spring Data JPA、Flyway、MySQL 8.4 LTS | 实体关系、查询、数据库版本迁移 |
| 认证 | 账号密码、BCrypt、JWT | 用户与管理员共用登录入口，角色控制后台权限 |
| 测试 | JUnit 5、Spring Boot Test、Vitest | 服务端业务与接口、前端逻辑校验 |

服务端按 `controller → service → repository` 分层：Controller 接收参数和返回响应；Service 处理权限与业务事务；Repository 访问 MySQL。文件由独立的媒体服务读写。`src/` 中建立工程时锁定具体补丁版本，并把启动命令写入各端说明。技术选型记录在 `decisions/0001-tech-stack.md`。

## 6. 运行与存储

- 开发环境使用 MySQL 8.4；数据库连接、JWT 签名密钥、媒体目录通过环境变量配置。
- 图片和视频保存到服务端配置目录，数据库只保存相对存储键、类型和上传者。客户端通过 `/api/v1/media/{id}/content` 访问。
- 小程序、管理后台共用 `/api/v1`；本地课堂演示使用微信开发者工具和本机运行的服务端。若改为真机演示，需配置可访问的 HTTPS 服务地址。
- 统计图加分项使用 Apache ECharts；其他加分功能按 `tasks.md` 排期。

## 8. 权限矩阵

| 操作 | 未登录 | 普通用户 | 动态作者 | 管理员 |
| --- | --- | --- | --- | --- |
| 浏览动态和评论 | 可以 | 可以 | 可以 | 可以 |
| 发布动态、上传媒体 | 不可 | 可以 | 可以 | 不可 |
| 修改/删除动态 | 不可 | 不可 | 可以 | 仅可删除任意动态 |
| 评分、评论他人动态 | 不可 | 可以 | 不可对本人动态操作 | 不可 |
| 修改本人密码 | 不可 | 可以 | 可以 | 可以修改本人密码 |
| 查询/删除用户及所有动态 | 不可 | 不可 | 不可 | 可以 |

权限在服务端校验，前端隐藏按钮只能改善体验，不能代替授权判断。

## 9. 主要处理流程

### 发布动态

小程序选择媒体 → 服务端验证文件并返回媒体 ID → 小程序提交文本、媒体 ID 和标签 → 服务端验证媒体归属与组合规则，保存动态及关联记录 → 返回详情。分步上传后 24 小时仍未绑定动态的文件与记录由清理任务移除。

### 检索与互动

小程序传入日期范围、标签和分页参数 → 服务端筛选动态并按创建时间倒序返回 → 用户进入详情后提交评分/评论 → 服务端检查身份及动态状态 → 更新或插入记录 → 返回最新评分摘要或评论。

### 管理操作

管理员登录 → 管理后台查询用户或动态 → 服务端检查管理员角色 → 执行逻辑删除或禁用 → 列表刷新。删除前页面显示确认提示；服务端记录操作者、对象、时间与操作类型。

## 10. 非功能与质量要求

- **安全**：密码哈希存储；校验文件类型与大小；避免越权访问；接口输入做长度和格式校验。
- **体验**：手机端页面清晰，上传有进度与失败提示；后台表格支持分页、空状态和删除确认。
- **可维护**：接口返回格式统一，业务逻辑不堆在控制器；跨端字段以 `contracts/` 为准。
- **可测试**：认证、本人权限、上传、检索、评分、评论和管理员操作应有可复现验收记录。
- **演示可靠性**：准备虚构账号和样例媒体；演示环境与启动步骤写入 `src/README.md`。
