# 项目提案与需求范围

## 1. 项目目标

开发一个类似朋友圈的多媒体展示系统，包含用户小程序、服务端和管理员 Web 后台。用户能够发布、检索和管理自己的图文视频动态，并对其他人的动态评分、评论；管理员能够查询、删除用户及动态。系统用于小组协作开发和课堂展示，功能验收以课程要求为准。

## 2. 角色与核心范围

| 编号 | 角色 | 需求 | 优先级 | 最低验收标准 |
| --- | --- | --- | --- | --- |
| U01 | 用户 | 登录、设置或修改自己的登录密码 | 必做 | 本人能登录并修改密码；其他人不能修改其密码 |
| U02 | 用户 | 发布文本、图片、视频内容 | 必做 | 三种媒体类型均能保存并在动态详情中展示 |
| U03 | 用户 | 查看、修改、删除自己发布的内容 | 必做 | 本人操作成功；非本人不能修改或删除 |
| U04 | 用户 | 给动态添加标签，按日期和标签检索 | 必做 | 两种筛选均可用，结果与条件一致 |
| U05 | 用户 | 浏览他人动态并评分、评论 | 必做 | 评分与评论能显示，评论与用户和动态正确关联 |
| A01 | 管理员 | 查询和删除用户 | 必做 | 管理员可以查找用户并执行删除；普通用户无此权限 |
| A02 | 管理员 | 查询和删除所有用户动态 | 必做 | 管理员可以查找动态并执行删除；普通用户无此权限 |
| N01 | 全部 | 界面良好、格式工整、代码风格良好 | 必做 | 主要页面布局一致，核心流程无明显错误，代码可阅读 |

具体业务规则见第 5 节，接口与数据字段见 `contracts/`。

## 4. 演示与交付成功标准

课堂演示至少覆盖：用户登录 → 发布图文或视频动态 → 按标签或日期检索 → 另一用户评分和评论 → 作者修改或删除自己的动态 → 管理员查询并管理用户和动态。应准备可复现的演示数据。

最终按小组提交：实验代码、实验报告、老师要求的四个附件表格、课堂展示 PPT。附件表格的正式名称和格式待收到模板后补充，交付位置见 `../deliverables/README.md`。

## 5. 项目业务规则

- 用户通过账号和密码注册、登录。动态广场、详情和评论可公开浏览；发布、评分、评论和个人设置需要登录。管理员账号由初始化脚本创建。
- 一条动态允许纯文本、1–9 张图片，或 1 个 MP4 视频；文本可与图片或视频同时存在，图片与视频不能混合。文本与媒体至少有一项非空。
- 图片接受 JPEG、PNG、WebP，单张不超过 10 MB；MP4 视频不超过 50 MB。媒体文件存储在服务端本地目录。
- 一条动态最多添加 5 个标签，标签长度为 1–20 个字符；日期和单个标签筛选可组合使用，列表按发布时间倒序分页。
- 其他用户可对动态打 1–5 分；同一用户对同一动态只有一条评分，可再次提交以修改分值。平均分显示到 1 位小数。
- 评论只支持一级评论，长度为 1–500 个字符；动态作者不能给自己的动态评分或评论。
- 用户只能编辑、删除自己的动态；管理员可删除任意用户和动态。删除动态采用逻辑删除，列表与详情不再展示；删除用户将其设为禁用状态并隐藏其动态。
- 修改密码会使原密码失效并撤销该用户已有的登录令牌。管理员删除用户后，该用户不能继续登录或访问受保护接口。

## 6. 技术栈

用户端采用 **uni-app + Vue 3 + TypeScript**，管理后台采用 **Vue 3 + TypeScript + Vite + Element Plus**，服务端采用 **Java 21 + Spring Boot 3.5 + Spring Security + Spring Data JPA + Flyway**，数据存储使用 **MySQL 8.4 LTS**。身份认证使用 JWT，密码使用 BCrypt 哈希。具体模块划分见 `design.md`。

## 7. 初版用户旅程与页面

| 角色 | 页面或场景 | 完成的事 |
| --- | --- | --- |

## 8. 端到端验收场景

1. 用户甲登录并发布含文本、图片与标签的动态；在广场和“我的动态”中都能看到。
2. 用户甲发布视频动态；用户乙能打开详情并播放视频。
3. 用户乙用日期或标签筛选出用户甲的动态，评分并评论；详情显示评论和评分摘要。
4. 用户甲修改自己的内容并删除其中一条；用户乙尝试修改或删除用户甲的动态时被拒绝。
5. 用户甲修改登录密码；旧密码失效，新密码可用于重新登录。
6. 管理员查询指定用户和动态并删除；普通用户调用管理接口时被拒绝。

每个场景须有可复现的测试数据与验收记录。加分功能如被纳入范围，应另补验收场景。
