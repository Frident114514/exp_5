# 0002 M02 在主工程未就绪时的模块组织

- 日期：2026-11-18。
- 状态：已用于 M02 独立实现；主工程整合和跨成员契约待真实联调确认。
- 背景：当前 `src/backend/` 仅有占位文件，M01 认证/公共配置、M03 媒体、M04 互动尚未提供代码；用户要求推进成员 02 的任务。

## 决定

在 `src/backend/modules/posts/` 建立可独立构建的 JAR，锁定 Java 21 与 Spring Boot 3.5.16，保持原有技术栈。模块实现动态、标签、检索和管理员内容 API；通过四个端口对接登录身份、媒体绑定、评分摘要及管理日志。

生产包不包含模拟身份、模拟媒体或无条件放行逻辑。测试夹具只在 `src/test/` 中提供，自动化测试以真实 MySQL 8.4 验证 M02 的迁移、查询、约束和事务，但不代表其他成员的功能已经实现。

迁移以候选 SQL 交付，合入前由 M01 分配全组 Flyway 版本号；测试 V1 为依赖夹具、V2 为候选 SQL，仅用于空库验证。M01 可把模块作为子模块或依赖引入，后续不必重新实现动态逻辑。

## 影响与交接

- `IdentityPort`、`MediaPort`、`RatingPort`、`AdminAuditPort` 必须有真实适配器才能运行完整接口。
- `PostAccess` 单独提供可见性检查与事务内锁，避免媒体/互动反向依赖 PostService 而形成循环依赖。
- `AuthorPosts.hideByAuthor` 要求调用方已有事务，用户禁用的总事务仍由 M01 编排。
- 暂时在模块内提供同形状的响应/错误处理；整合全组公共类时由 M01 核对并合并。
- S4 真实联调和同伴验收保持未完成；测试夹具的成功不得替代这些门槛。
